# CTCS-2 TCC 七类答辩演示场景

## 通用准备

1. 在项目根目录运行 `python run_dual.py`，只启动一个双站同屏窗口。
2. 顶部全局状态条显示“通信健康”，区间改方页显示 A/B 方向一致且“联合锁闭：否”。
3. 如上次演示留下状态，先取消进路、撤销临时限速、清除人工/故障输入并复位列车。
4. 每个场景观察总览、轨道编码、信号、应答器/LEU、网络和日志告警页。

## 1. 全空闲基线

- 目标：`A站控制` 页面，目标站 `A站`。
- 前置：A/B 通信为 `HEALTHY`；Q1～Q4 空闲；方向为 `A_TO_B`。
- 操作：进入“总览拓扑”，选择 `A_DEPART`，单击“建立进路”。
- 预期：配置化区间码序正常形成；SA 灯色由其防护区段码序唯一导出；正常逻辑报文被选中。
- 复位：取消 `A_DEPART`。

## 2. 区间占用

- 目标：`轨道电路` 页面，目标 `A/B双站（共享区间）`。
- 前置：A/B 通信健康且共享 Q 区段状态一致。
- 操作：目标选择“共享区间”，将 Q3 设置为“占用”并应用。
- 预期：Q3 为保护码；后方区段按距离逐级降级；相关信号不得错误开放；操作进入历史日志。
- 复位：把 Q3 的人工来源改为空闲。

## 3. 轨道故障/分路不良

- 目标：`轨道电路` 页面，目标 `A/B双站（共享区间）`。
- 前置：Q2 一致空闲；联合列车已复位或尚未创建。
- 操作：将 Q2 设置为“故障占用”或“分路不良”；也可让列车进入 Q2 后再写入人工故障来源。
- 预期：Q2 保持保护码并影响后方码序；列车跨区或复位只清除 `TRAIN` 来源，故障仍保留。
- 复位：明确清除 Q2 的故障来源，再复位列车。

## 4. 红灯灯丝故障

- 目标：`信号机控制` 页面，示例目标站 `A站`。
- 前置：A/B 通信健康，SA 存在于配置。
- 操作：选择 A站、SA，勾选红灯灯丝故障并单击“应用灯丝状态”。
- 预期：灯色为 `RED_LAMP_FAILURE`，HJ/UJ/LJ 均落下，产生严重告警并保持保护状态。
- 复位：取消灯丝故障选项。

## 5. 临时限速与应答器报文

- 目标：`临时限速` 页面，示例目标站 `A站`；结果到 `应答器/LEU` 页面查看。
- 前置：A站不存在同名未撤销命令；里程和有效时间合法。
- 操作：预存 `TSR-DEMO`（例如 1000～3000 m、80 km/h），再执行。
- 预期：LEU 选择限速模板；逻辑报文含 CTCS-2 限速字段；教学位流、HEX、CRC32 明确标记为仿真封装。
- 复位：撤销 `TSR-DEMO`。

## 6. 正常区间改方

- 目标：`区间改方` 页面，目标 `A/B双站`，命令固定由 A 发起。
- 前置：Q1～Q4 空闲、无活动进路、通信健康且 A/B 方向一致。
- 操作：选择 `B_TO_A`，单击“由A站申请区间改方”。
- 预期：依次完成 PREPARE、APPROVE、COMMIT、ACK/确认；A 先持久化权威方向；双方最终为 `B_TO_A` 并解除锁闭。
- 复位：在相同安全条件下由 A 改回 `A_TO_B`。

## 7. 改方中断线

- 目标：先在 `区间改方` 页面发起，再到 `通信状态` 页面观察 A/B。
- 前置：A/B 初始通信 `HEALTHY`，且区间满足改方条件。
- 操作：在“区间改方”页选择目标方向，单击“发起改方并立即中断B站”；该组合动作保证先由 A 排队改方请求、再注入 B 站链路故障，避免人工切页速度影响复现。观察锁闭后进入“通信状态”页单击“恢复B站网络”。故障按钮会真实关闭当前 TCP 会话并控制自动重连，但不会关闭控制器或整个窗口。
- 预期：不回滚已经提交的 A 权威方向；双方相关作业立即锁闭、信号红灯；重连全量同步后按 A 权威方向和持久化恢复证据恢复。
- 复位：等待两站重新显示 `HEALTHY` 且方向一致；若条件不满足，保持锁闭并检查日志告警，不强行解锁。

## 列车演示补充

当前方向为 `A_TO_B` 时在 A 建立 `A_DEPART`，随后在“列车演示”页依次单击“添加待发列车”“发送选中列车”“开始仿真”；反向时在 B 建立 `B_DEPART`。唯一联合协调器按 `A_T1 → A_T2 → Q1～Q4 → B_T2 → B_T1`（反向严格逆序）运行，区段顺序和长度来自 `configs/topology.json`，没有 G01～G08 硬编码。状态表持续显示列车 ID、方向、区段、位置、当前/目标速度、前方距离、最后应答器和安全状态。该动画只用于观察 TCC 联动，不表示真实列车动力学、制动曲线或车载 ATP 行为。

## 操作结果判读

轨道、信号、限速、改方和列车页面底部均显示“目标、成功/拒绝、原因、状态版本”。出现拒绝时不得绕过控制器强行改状态；应先按原因恢复前置条件。共享轨道操作若只成功写入一站，将保留已写入的保守状态、产生 `SHARED_INPUT_PARTIAL_FAILURE` 严重告警，并保持联合安全锁闭。
