## 1. 需求冻结

本轮开发遵守以下约束：

1. 需求、术语、图形、业务范围和示例全部以 Word 为准；既有 PDF 和旧方案不再作为验收依据。
2. 暂不建设事件记录模块，也不在界面预留对应区域。
3. 只展示下行线的业务状态，但模型保留方向字段，以支持 A→B、B→A 改方演示。
4. 站内只实现正线接车、侧线接车、正线发车、侧线发车及进路取消。
5. 7.1 是画图的硬约束：必须把 A 站、A—B 区间和 B 站画成一张连续长图；区间共有 38 个轨道区段，每两个轨道区段组成一个闭塞分区，因此共有 19 个闭塞分区。
6. 图中应有股道、道岔、区段边界、信号机、轨道电路码带、列车、有源/无源应答器。Word 中有源应答器组采用实心三角形、无源应答器采用空心三角形；黑底下用高亮实心和浅色空心保持同一语义。
7. 页面采用“上方大幅 2D 区、左下 A/B 站通信区、右下仿真操作区”的布局，控件不得拥挤。
8. 每个阶段都要先通过自动测试和人工检查，再更新 `PROGRESS.md`、提交 Git 并推送 `origin`。

## 3. 软件结构

```text
ui/                         只负责绘图、展示和输入
models/                     轨道、信号、进路、列车、应答器、限速状态
services/                   进路、编码、点灯、报文、改方、列车推进规则
network/                    A/B TCC 的 TCP/IP 消息交换
tests/                      规则和界面合同测试
docs/phases/                每一阶段的技术说明及验收记录
PROGRESS.md                 唯一续做入口
```

界面不能直接决定安全状态。每次操作只产生领域事件，服务层完成校验和计算后，再用一份完整状态刷新界面。

固定计算顺序：

```text
接收操作或站间消息
→ 校验方向、进路冲突、区段占用和通信条件
→ 更新进路及列车位置
→ 更新轨道占用
→ 按当前方向计算区间和站内编码
→ 根据信号规则计算灯色
→ 选择有源应答器信息包
→ 计算列车目标速度
→ 生成完整界面状态
```

## 4. 关键状态与规则

### 4.1 轨道区段

每个区段至少保存：`id`、`station_or_interval`、`neighbors`、`occupied`、`route_id`、`send_direction`、`track_code`、`length_m`。占用显示和实际发码分开：界面红光带显示为 `B`，不能把 `B` 当作低频码。

### 4.2 进路

四类进路：

- `MAIN_RECEIVE`：正线接车；
- `SIDE_RECEIVE`：侧线接车；
- `MAIN_DEPART`：正线发车；
- `SIDE_DEPART`：侧线发车。

状态机：

```text
IDLE → CHECKING → LOCKED → SIGNAL_OPEN
                        ↘ CANCELLED
SIGNAL_OPEN → OCCUPIED → RELEASED
```

排列条件：路径区段空闲、无冲突进路、方向允许、道岔位置可转换并锁闭。取消条件：列车尚未进入；进入后的进路只能随列车运行解锁，不能直接清除。

当前方向为 A→B 时，只允许 A 站建立发车进路、B 站建立接车进路；B→A 时规则镜像。重复建立同一进路、同站建立第二条进路或两端同时建立对向发车进路均被拒绝，并在弹窗中列出现有进路、请求进路和处理建议。

### 4.3 轨道电路编码

课程码序采用 Word 示例中的：

```text
HU → U → LU → L → L2 → L3 → L4 → L5
```

算法按当前运行方向构造有向区段序列。以列车占用区段为停车目标，目标后方逐段向外给出更宽松码；越靠近停车目标，限制越严。边界处必须读取邻站首区段和接车进路状态，保证码序连续。

规则优先级：

1. 区段占用：界面显示红光带 `B`；
2. 进路或方向不允许：限制到 `HU` 或无码；
3. 侧线 18 号及以上道岔发车：入口相关区段发 `UUS`，但出站信号机按 Word 示例显示 L 灯；
4. 正线发车：车出站后站内占用区段显示 `B`，区间从入口向前形成 `L4、L3、L2、L、LU、U、HU…` 的动态序列；
5. 前方状态变化后，从停车目标向反方向一次性重算，禁止逐控件临时修补。

站内 `1G`、`3G` 和区间侧咽喉均显示低频码带。无进路时使用限制码 `HU`；正线发车时 `1G` 与咽喉码跟随相邻区间入口码，保证站内外码序连续；正线接车以股道停车目标为边界，站内保持 `HU`；侧线接发车时对应 `3G` 与咽喉使用 `UUS`。列车占用时红光带与低频码状态分别保存，显示占用不得覆盖业务编码源。

示例：列车位于靠近 B 站的 G37，G38 空闲且 B 站未开放接车进路，则 G36 及其后方依次显示较限制码；B 站开放正确接车进路后，边界目标延伸进站内，G38 和后方区段随之升级。

### 4.4 信号机点灯

信号显示由进路、方向、首区段占用和前方码共同决定，不能由按钮直接设置。

| 条件 | 结果 |
|---|---|
| 无进路、进路冲突、方向不允许或首区段占用 | 红灯 |
| 前方目标要求停车 | 红灯或黄灯，按 Word 场景表 |
| 前方为 U | 黄灯 |
| 前方为 LU | 黄绿灯 |
| 正常开放且前方为 L/L2/L3/L4/L5 | 绿灯 |
| 侧线 18 号及以上发车 | 轨道码可为 UUS，信号显示 L 灯 |

Word 7.6 的特殊演示模式启用后，列车通过的区段红光带保留，列车后方通过信号机熄灭；该模式必须有显式开关并与正常出清逻辑分开。

### 4.5 有源应答器

只对有源应答器组提供点击查看。通信未建立时显示 `ETCS-254`。通信建立后按位置和进路组合信息包：

每个有源应答器组固定绘制 3 枚紧凑实心三角形，并放在对应钢轨与轨道电路码带之间：`JZ` 位于 X 进站信号机左侧区段下方；`FJZ` 位于 S/SN 进站信号机右侧区段下方；`CZ` 分别位于 X1、X3 出站信号机左侧股道；`FCZ` 分别位于 S1、S3 出站信号机右侧股道。每一组均建立独立点击命中区域。

| 应答器组/场景 | 信息包组合 |
|---|---|
| JZ 正线接车 | ETCS-5、ETCS-44(CTCS-2，存在临时限速时) |
| JZ 侧线接车 | ETCS-5、ETCS-27、ETCS-68、ETCS-44(CTCS-1)、按需 CTCS-2 |
| FJZ 关闭信号 | ETCS-5、ETCS-132、ETCS-137 |
| CZ/FCZ 侧线发车 | ETCS-5、ETCS-27、ETCS-68、CTCS-1、按需 CTCS-2 |
| DD 且 UUS 条件 | ETCS-5、ETCS-44(CTCS-4) |

弹窗显示信息包名称、触发条件和关键字段，不生成真实车载二进制报文。

### 4.6 临时限速

支持设置和取消。限速对象保存范围、方向、速度、状态和版本。新限速与任何活动限速共享一个或多个轨道区段时拒绝建立，并显示新旧范围、速度和冲突编号；两个范围仅相邻且不共享区段时允许并存。列车目标速度取线路速度、轨道码允许速度、进路速度、临时限速中的最小值。`CTCS-2` 仅在实际存在有效临时限速时加入报文。

仿真时钟提供 `0.5×、1×、2×、5×、10×、20×` 六档倍速；倍速只改变仿真时间步，不改变编码、进路和安全条件。

### 4.8 操作门禁、启动校验与复位

- 只有 A、B 两站均完成实际连接，改方、进路、临时限速、列车和仿真按钮才可用；每个处理函数还会再次校验通信状态，避免绕过界面禁用状态。
- 添加列车时只创建未指定接发方式的待发列车。点击“发车”时，以“查看列车”当前选中项为唯一目标，读取界面当前发车/接车方式和最大速度，核对当前方向下的两端进路与前车间隔；校验通过后才写入配置并发出该车，其他待发列车保持不变。
- 仿真运行期间仍可继续选中并发出满足条件的待发列车。发车后的接发方式锁定；最大速度在运行和暂停状态仍可调整并实时影响目标速度。
- 暂停/继续控制全部已经发车的列车；复位把全部运行、暂停和已到达列车送回出发点并重新加入待发队列。复位保留列车接发配置、最大速度、临时限速和全部人工建立进路，只解除列车造成的占用与锁闭。
- 一键清车暂停仿真并清除全部待发、运行、停车和到达列车，同时清空区段占用；已建立进路继续保留并恢复为“已建立、未锁闭”。
- 发车进路在列车驶入第二区段后解除锁闭，接车进路在列车到达后解除锁闭；两类进路均不会自动删除，只能由用户点击“取消选中进路”人工取消。
- 所有可预期业务错误统一显示“操作失败、当前状态、处理建议”，不得只显示异常字符串或内部堆栈。

多列车推进使用同一时钟周期的位置快照，并按运行方向从前到后更新。全部运行或暂停列车共同形成轨道占用集合；多个占用点分别生成防护码，影响范围重叠时采用允许速度更低的编码。入口占用或前车尚未越过第三个区段时拒绝后车发车，确保入口后至少保留两个完整轨道区段。详细实现和验收见 `docs/phases/PHASE-05.md`。

### 4.7 区间改方

严格实现 Word 第 6 节的四步简化流程：

1. B 站排列发车进路，CBI 向 B-TCC 发送发车请求和方向锁闭状态；
2. B-TCC 检查全区间空闲且 A 站无发车进路，向 A-TCC 发送改方请求；
3. A-TCC 再校验后切为接车方向，并向 B-TCC 返回许可；
4. B-TCC 切换方向，向本站 CBI 返回允许发车和方向信息。

状态机：`IDLE → REQUESTED → REMOTE_CHECK → APPROVED → SWITCHED`，任一步失败进入 `DENIED` 并保持原方向。区间占用、对方已办发车、通信中断或请求超时均拒绝改方；禁止两端分别在本地直接切方向。

## 7. 总体验收示例

### 示例 A：正线发车

初态 A 站列车位于 1G，未排列进路。点击发车应被拒绝。排列正线发车进路后，相关道岔锁闭，出站信号开放。列车进入区间后，站内占用显示红色，出站信号关闭，区间码序按前方状态重新计算。

### 示例 B：侧线 18 号及以上道岔发车

列车位于 3G。排列侧线发车进路后，相关轨道码显示 UUS；按 Word 示例，信号机显示 L 灯。列车经过道岔后，后续区间恢复按常规码序计算。

### 示例 C：改方

初始方向 A→B。B 站排列发车进路并申请改方；区间空闲且 A 无发车进路时，按四步流程改为 B→A。若先占用任一区间分区，申请必须失败，双方仍保持 A→B。

### 示例 D：临时限速与应答器

在 G03～G05 设置 80 km/h，列车进入范围前目标速度降至不高于 80 km/h；相关有源应答器详情出现 CTCS-2。取消后，目标速度按其余约束恢复，CTCS-2 从报文组合移除。
