# TCC 多列车发车与追踪控制设计

日期：2026-10-11

## 1. 背景与目标

当前程序已经能够保存多辆列车，但仿真启动仍围绕单个 `dispatch_target_id` 运转，按钮语义同时承担“配置列车、发车、继续仿真”三种职责。暂停期间再添加列车后，后添加列车还可能覆盖原有目标，造成用户选中的列车与实际启动列车不一致。

本次修订把列车选择、单车发车和全局仿真控制拆开：用户每次只发出“查看列车”中当前选中的一辆待发列车；所有已发车列车由同一个仿真时钟同时运行；暂停、继续和复位作用于全部已发车列车。轨道占用、低频编码和信号显示根据全部列车的实时位置共同计算。

## 2. 范围

本次包含：

- 多辆列车同时运行；
- 当前选中列车单独发车；
- 当前选中列车状态展示；
- 发车后锁定接发车方式；
- 全局暂停、继续和复位；
- 多车占用、追踪间隔、编码和信号联动；
- 每辆列车独立的最大速度及运行中实时调整；
- 完整、可操作的错误弹窗；
- 对应自动化测试、进度文档和阶段性 Git 提交。

本次不改变 38 个区间轨道区段、19 个闭塞分区、站场物理设备位置、进路类型和临时限速范围规则，也不新增日志模块。

## 3. 方案选择

采用“每车保存运行配置、单车立即发车、全局时钟统一推进”的方案：

- `Train` 保存本车接发方式、最大速度、状态和运行约束；
- `TrainService` 接收明确的列车编号，只对该车执行发车校验和状态转换；
- `SimulationEngine` 每个时钟周期更新全部运行中列车；
- `MainWindow` 以列车选择框为唯一当前对象，负责展示该车信息并协调控件状态；
- `SimulationService` 根据全部轨道区段占用统一更新编码和信号。

不再保留“点击一次后等待未来自动发出”的隐式待发目标。点击“发车”时条件满足就立即发车；条件不满足则保持列车待发，并说明阻止发车的具体原因。这样不会因随后添加或选择另一辆车而改变原操作目标。

## 4. 列车状态与配置

列车继续使用以下生命周期：

```text
WAITING --发车成功--> RUNNING --全局暂停--> STOPPED
   ^                       |                  |
   |                       +------继续--------+
   +-----------全局复位----------------------+

RUNNING/STOPPED --到达终点--> ARRIVED --全局复位--> WAITING
```

### 4.1 添加列车

添加列车时只创建待发列车，不固化当时界面上的发车方式和接车方式。新增列车默认最大速度为 `120 km/h`。

### 4.2 发车配置

点击“发车”时，从当前界面读取发车方式、接车方式和最大速度，并写入当前选中的待发列车。只有校验全部通过后才进入 `RUNNING`。

为了在多个待发列车之间切换时保留用户设置，待发列车允许保存尚未生效的界面配置；但列车刚添加时仍保持未配置状态，不从上一辆列车继承属性。

### 4.3 发车后锁定

当前选中列车处于 `RUNNING`、`STOPPED` 或 `ARRIVED` 时：

- 发车方式和接车方式不可编辑；
- 切换到另一辆待发列车后恢复可编辑；
- 最大速度在 `RUNNING` 和 `STOPPED` 状态仍可编辑并立即生效；
- 到达列车的最大速度只显示，不再接受修改。

## 5. 界面与按钮语义

### 5.1 列车实时运行状态

“查看列车”选择框是列车状态区的唯一选中来源。切换列车时同时刷新：

- 当前区段和区段位置；
- 当前速度和目标速度；
- 当前码序、线路限速和最大速度；
- 最后应答器、安全状态、前车距离和制动距离；
- 发车方式、接车方式和最大速度控件；
- 发车、暂停/继续、复位和清车按钮状态。

### 5.2 发车按钮

“▶ 开始仿真”改为“▶ 发车”。一次点击只尝试发出当前选中的一辆 `WAITING` 列车。

发车成功后：

1. 锁闭该车使用的接发进路；
2. 将列车置为 `RUNNING` 并进入起始区段；
3. 若全局时钟尚未运行，则启动时钟；
4. 立即刷新全部占用、编码、信号和界面状态。

若列车不满足条件，不设置延迟发车目标，也不影响其他运行列车。

### 5.3 暂停与继续

暂停按钮作用于全部 `RUNNING` 列车：

- 点击“Ⅱ 暂停”后停止全局时钟，并将全部运行列车置为 `STOPPED`；
- 按钮随后显示为“▶ 继续”；
- 点击“▶ 继续”后恢复全部可继续运行的停车列车和全局时钟；
- 暂停期间仍允许复位和一键清车；
- 暂停期间允许选择待发列车，但必须先继续仿真或在发车成功时由系统恢复全局时钟。

发车按钮不承担“继续”职责，避免一个按钮包含两种不相干的操作。

### 5.4 全局复位

复位作用于所有已经发车的 `RUNNING`、`STOPPED` 和 `ARRIVED` 列车：

- 停止全局时钟并把仿真时间归零；
- 将这些列车送回当前方向对应的出发点，并置为 `WAITING`；
- 清除列车造成的轨道占用；
- 将列车锁闭的进路恢复为“已建立、未锁闭”，不删除进路；
- 保留列车对象、最大速度和已选择的接发方式，复位后允许用户重新编辑；
- 保留临时限速；
- 重新计算全部编码、信号和按钮状态。

从未发车的待发列车保持原状。一键清车仍清除全部待发、运行、停车和到达列车，并释放其占用和锁闭，但不删除人工建立的进路及临时限速。

## 6. 最大速度

在“接车方式”右侧增加“最大速度”选择框，固定选项为：

```text
80、120、160、200、250、300、350 km/h
```

默认值为 `120 km/h`，以保持现有仿真速度和测试基线。最大速度是列车自身上限，不覆盖更严格的线路、编码、应答器、临时限速或追踪限制。

列车最终目标速度按下式确定：

```text
目标速度 = min(
    列车最大速度,
    当前低频码允许速度,
    线路限速,
    有源应答器限速,
    临时限速,
    前车追踪允许速度
)
```

运行中降低最大速度时，只改变目标速度，列车按既有制动模型减速，不瞬间修改当前速度；提高最大速度时仍受其他限制约束。

## 7. 多车运行与安全间隔

### 7.1 统一推进

每个仿真周期按稳定的列车编号顺序处理全部 `RUNNING` 列车。移动前先取得本周期占用快照和同向前车位置，计算各车目标速度；移动后统一提交新的占用状态，避免某辆车先更新造成同一周期内前后车判断不一致。

### 7.2 区段互斥

任何时刻一个轨道区段最多允许一辆列车占用。后车准备进入前方区段时，如果区段仍被占用，则禁止越界并执行停车或制动。

### 7.3 发车间隔

发出后续列车前必须同时满足：

- 当前方向正确；
- 对应接发进路均已建立且方式匹配；
- 出发入口区段空闲；
- 最近同向前车至少位于第三个区段，即与入口之间保留两个完整轨道区段；
- 进路没有被其他列车锁闭；
- 站间通信完整。

若间隔不足，弹窗显示前车编号、所在区段和当前距离，不自动排队等待。

### 7.4 前车追踪保护

同向列车按线路累计位置排序。后车使用最近前车的距离、当前速度、制动距离和安全余量计算追踪允许速度：

- 距离大于安全制动需求时按正常编码运行；
- 距离进入减速区时逐级降低目标速度；
- 距离小于最小安全余量或前方区段占用时目标速度降为 0；
- 禁止后车累计位置超过前车或进入同一区段。

反向列车在正常业务规则下不会同时进入同一区间；已有改方、方向和进路门禁继续阻止这种冲突。

## 8. 轨道电路编码与信号联动

编码计算以“全部列车形成的区段占用集合”为唯一输入，不直接用某个界面选中列车驱动。

每次发生发车、移动、暂停、继续、复位、清车或到达后：

1. 汇总所有 `RUNNING` 和 `STOPPED` 列车的占用区段；
2. 将占用区段设置为停车防护码；
3. 从每个占用点向后按闭塞分区重新生成 `HU、U、LU、L、L2、L3、L4、L5` 等码序；
4. 多个占用点的防护范围相交时采用更严格的码；
5. 站内股道和咽喉区段继续根据接发进路与区间入口码联动；
6. 信号机依据当前方向、进路状态、入口空闲和前方码显示允许或禁止信号。

因此前车前进、后车追踪或两车间隔缩小时，后车前方的轨道码和相关信号会自动降级；间隔恢复后再按占用状态逐级升级，不写死为某辆列车专属信号。

## 9. 错误操作反馈

所有拒绝操作使用完整三段式信息：

```text
操作失败：<明确结论>

当前状态：<列车、方向、区段、距离、进路或通信信息>
处理建议：<下一步可执行操作>
```

至少覆盖：

- 未选择列车；
- 当前列车不是待发状态却点击发车；
- 双站通信未建立；
- 缺少发车或接车进路；
- 接发车方式与进路不一致；
- 进路已被其他列车锁闭；
- 出发入口区段被占用；
- 前车间隔不足；
- 当前没有运行列车却点击暂停；
- 当前没有已发车列车却点击复位；
- 没有列车却点击一键清车；
- 发车后尝试修改接发方式；
- 最大速度不在允许选项内。

任何校验失败都不得部分修改列车、进路、占用、计时器或选择框状态。

## 10. 服务接口调整

### 10.1 `TrainService`

- 删除或停用单一的延迟 `dispatch_target_id` 机制；
- 新增按列车编号立即发车的接口，返回明确成功结果或业务错误；
- 提供 `pause_all()`、`resume_all()` 和 `reset_dispatched_trains()`；
- 每周期计算全部运行列车的前车关系、速度约束和下一位置；
- 统一同步区段占用后再触发编码和信号更新。

### 10.2 `Train`

- 最大速度进入状态快照；
- 区分当前速度与最大速度；
- 保留接发方式和复位后的可编辑状态；
- 提供是否已经发车、是否允许修改方式和是否允许修改最大速度的状态判断。

### 10.3 `MainWindow`

- 发车事件始终读取列车选择框当前编号；
- 选择变化时同步信息和控制栏；
- 模式选择框按选中列车状态锁定；
- 最大速度变化写入当前选中列车并刷新目标速度；
- 暂停按钮在“暂停/继续”之间切换；
- 所有控制状态由统一刷新函数计算，事件处理函数仍进行第二次业务校验。

## 11. 测试与验收

采用测试先行，至少覆盖：

1. 发车按钮只发出当前选中的待发列车，其他待发列车不变；
2. 暂停期间添加或选择另一辆车不会覆盖原运行列车；
3. 两辆及以上列车能同时推进，且永不占用同一区段或发生超越；
4. 第二辆车在间隔不足时被拒绝，满足两个完整区段间隔后可发车；
5. 多个占用点共同生成最严格码序，入口信号随间隔关闭和开放；
6. 选中不同列车时实时状态、接发方式和最大速度正确切换；
7. 发车后接发方式锁定，复位后解锁；
8. 最大速度包含七个固定选项，默认 120，运行中修改立即影响目标速度；
9. 暂停/继续控制全部运行列车；
10. 复位把全部已发车列车送回出发点，保留列车、进路和临时限速；
11. 一键清车清除全部列车并解除锁闭，但保留进路；
12. 各类非法操作弹窗信息完整，且失败前后业务状态不变；
13. 既有 38 区段、19 闭塞分区、站场绘制、通信、进路和限速测试全部回归通过；
14. 1600×760 及常用窗口尺寸下新增最大速度控件无挤压、遮挡和文字裁切。

## 12. 完成标准

- 自动化测试、语法检查和差异格式检查全部通过；
- 关键多车场景具有可重复测试；
