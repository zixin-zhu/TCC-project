# 站内连续运动、信号码序联动与全进路复位设计

日期：2026-10-12

## 1. 目标

本次修订解决以下六类一致性问题：

1. 待发列车只绘制一个车体，车体上方的 xN 表示当前待发列车总数。
2. 列车发车后从出发站外方信号机旁的待发位置起步，完整经过发车进路后再进入 G01/G38。
3. 正线列车沿直轨运行，侧线列车沿咽喉斜坡和 3G 折线路径连续运行，不发生纵向跳变。
4. 区间和站内信号机灯色统一由所防护轨道电路码序、进路和运行方向决定。
5. 状态栏中的发车方式、接车方式和当前列车状态改为普通文字，不使用输入框式外观。
6. 全局复位时取消所有进路、清除列车接发方式，并立即同步状态栏、码序和信号。

本次保留既有 38 个区间轨道区段、19 个闭塞分区、多车间隔防护、临时限速、通信门禁和应答器位置。

## 2. 领域状态机

列车运行阶段统一为：

```text
WAITING
  → DEPARTING
  → INTERVAL_RUNNING
  → WAITING_RECEIVE_ROUTE（需要时）
  → RECEIVING
  → STATION_RUNNING
  → EXITING
  → ARRIVED
```

### 2.1 待发

- A→B 待发列车逻辑位置位于 A站 X 信号机右侧。
- B→A 待发列车逻辑位置位于 B站 S 信号机左侧。
- 多辆待发列车仍作为独立列车对象保存在待发队列，但2D图只绘制一个车体。
- 车体标签为 xN，N 等于当前方向和出发站的待发列车数量。

### 2.2 发车进路运行

列车点击“发车”后不再立即调用 enter_track(G01/G38)，而是：

1. 锁闭并绑定当前发车进路。
2. 保存由进路派生的 MAIN/SIDE 发车方式。
3. 进入 DEPARTING 阶段，建立出发站内连续位置。
4. 按仿真时钟沿站内路径推进。
5. 越过区间侧外方信号机后进入 G01 或 G38。
6. 此时删除已使用的发车进路、清空 departure_route_id，并读取首个区段应答器。

入口区段在 DEPARTING 阶段不占用；列车真正越过站界进入首个区段时才产生区间占用。

### 2.3 区间与接车

既有区间运行和最前车接车进路分配规则保持不变。没有接车进路时，列车继续停在目标站外方边界。获得接车进路后进入 RECEIVING，并沿目标站正线或侧线路径继续运行。

接车进路仍在：

- A→B 越过 B站 X1/X3；
- B→A 越过 A站 S1/S3；

后自动删除。列车随后经过站内与出站段，越过目标站另一端外方信号机后进入 ARRIVED。

## 3. 站内路径模型

### 3.1 路径坐标来源

所有路径点都由 TccOverviewWidget 的站场几何合同生成，禁止业务层复制像素坐标。绘图层根据：

- 车站 A/B；
- 运行方向 A→B/B→A；
- 当前阶段 DEPARTING/RECEIVING/STATION_RUNNING/EXITING；
- 进路股道 1G/3G；
- 0～1 的站内归一化进度；

计算列车实际绘制位置。

### 3.2 正线路径

正线路径为外方信号机之间的水平折线，所有路径点 rail_y 相同。

### 3.3 侧线路径

侧线路径由五段组成：

1. 出发侧外方信号机至下方咽喉点的正线；
2. 下方咽喉点至 3G 起点的斜坡；
3. 3G 起点至 3G 终点的水平侧线；
4. 3G 终点至另一侧下方咽喉点的斜坡；
5. 下方咽喉点至到达侧外方信号机的正线。

反方向运行使用同一组路径点的逆序，不另写一套镜像公式。

### 3.4 按路径长度插值

路径插值按各段欧氏长度累计，而不是只按横坐标百分比。给定归一化进度后：

1. 计算整条折线总长度。
2. 找到当前累计距离所属线段。
3. 在线段首尾之间线性插值 x、y。

因此列车进入或离开3G时会沿真实斜坡连续移动，不会从正线直接跳到侧线。

## 4. 多辆待发列车的显示

TccOverviewWidget 在绘制前按方向统计 WAITING 列车：

- A→B 只在 A站 X 右侧绘制一个待发标记；
- B→A 只在 B站 S 左侧绘制一个待发标记；
- 标签为 xN；
- 如果两个方向同时存在待发对象，则两个出发端各绘制一个数量标记。

列车选择框仍逐辆列出 T001、T002 等真实列车编号，发车操作仍只作用于当前选中列车。

## 5. 轨道码序与信号机灯色

### 5.1 唯一码序映射

SimulationService 作为码序—灯色的唯一规则来源：

| 轨道码 | 信号显示 |
|---|---|
| L5、L4、L3、L2、L | 绿灯 |
| LU | 黄绿灯 |
| U | 黄灯 |
| HU | 红灯 |
| UUS | L灯 |
| 未知或无有效防护码 | 红灯 |

绘图层不得为区间信号机写死“绿灯”。

### 5.2 区间信号机

每个区间信号机读取其运行方向前方所防护闭塞分区的当前码序，并通过统一映射得到灯色。反方向不开放的信号机显示红灯。

### 5.3 站内信号机

- S1/X1 等正线信号机读取 1G 或对应咽喉码。
- S3/X3 等侧线信号机读取 3G 码；UUS 显示 L灯。
- X、SN、S 等外方信号机读取相邻咽喉/区间码，并受方向、进路存在性和占用条件门控。
- 没有合法进路、方向不允许或防护区段占用时，门控结果优先为红灯。

传给2D图的状态快照必须包含每一架需要绘制的信号机状态，绘图组件只消费状态，不自行推断业务规则。

## 6. 状态栏样式

第一行继续保持：

```text
查看列车｜发车方式｜接车方式｜当前列车状态｜设置速度
```

其中：

- 查看列车和设置速度保留下拉框。
- 发车方式、接车方式、当前列车状态使用普通 QLabel。
- 删除 train_route_value/train_state_value 的边框、背景、圆角和左右内边距。
- 文本字重、字号和“当前分区、当前速度”等信息保持一致。
- 长文字保留足够最小宽度，1600×760 下不得覆盖相邻标签。

## 7. 全局复位语义

用户已确认复位时删除所有进路，包括与列车无关、预先建立但尚未使用的进路。

复位执行顺序：

1. 暂停仿真时钟。
2. 将全部 RUNNING、STOPPED、ARRIVED 列车恢复为 WAITING。
3. 清空每辆复位列车的 departure_mode、arrival_mode、station_track、arrival_track、route_id、departure_route_id、receive_route_id、station_position 和等待原因。
4. 调用 RouteService.clear_all() 删除全部发车和接车进路。
5. 释放全部区间占用并重新计算码序和信号。
6. 保留临时限速。
7. 刷新进路选择框、2D图和当前列车状态栏。

复位完成后，任何列车均显示：

- 发车进路尚未建立；
- 接车进路尚未建立；
- 当前列车状态为待发。

## 8. 异常与边界

- DEPARTING 期间再次点击发车应按非待发状态拒绝。
- DEPARTING 期间全局暂停和继续必须保持站内位置。
- DEPARTING 期间复位必须删除锁闭发车进路并回到单一待发标记。
- 多辆待发列车复位后，xN 必须立即更新。
- 无接车进路的停车逻辑不受发车阶段新增影响。
- 侧线接发车路径不得访问缺失的 S3/X3 坐标。
- 复位后信号不得保留旧进路产生的开放状态或 UUS/L灯状态。

## 9. 测试与验收

必须先写失败测试，再实现：

1. 多辆待发列车只生成一个 xN 标记。
2. 发车后首先进入 DEPARTING，尚未占用 G01/G38。
3. 正线和侧线路径端点正确，侧线中间点位于斜坡和3G上。
4. 四种方向/正侧线组合均连续进入区间。
5. 区间信号机灯色随所防护码序变化。
6. 站内正线、侧线信号机分别随 1G/3G 码变化，UUS 显示 L灯。
7. 状态栏三个只读值没有输入框式样。
8. 复位删除所有进路、清空接发方式、保留临时限速并刷新状态。
9. 多车、接车等待、进路自动释放等既有测试继续通过。
