# TCC 仿真操作门禁与错误反馈设计

日期：2026-10-10

## 1. 背景与目标

当前界面允许在站间通信尚未真正建立时操作进路、临时限速和列车仿真，部分按钮状态也没有随仿真生命周期同步变化。部分非法操作虽然会被底层条件间接拒绝，但提示不够具体；下拉菜单在 macOS 上还存在选中项白底白字的问题。

本次修订建立统一的操作门禁、方向相关进路规则、限速冲突规则、列车接发进路校验和按钮状态机，并统一错误弹窗与字体样式。目标是让用户在界面上清楚知道“为什么不能操作、当前状态是什么、下一步该怎么做”。

## 2. 范围

本次包含：

- 双站通信完成前的操作区门禁；
- 方向与进路类型的对应校验；
- 重复/冲突进路提示；
- 临时限速重叠冲突校验；
- 开始仿真前的列车接发方式校验；
- 暂停、复位、清车、取消限速等按钮状态；
- 复位时保留进路并解除锁闭；
- 通信中断自动暂停；
- 统一错误信息、字体与下拉菜单选中色。

本次不新增日志模块，不改变 38 个区间区段、19 个闭塞分区、码序、信号点灯和应答器信息包规则。

## 3. 设计原则

采用“业务服务负责规则，主窗口负责状态协调和展示”的方案：

- `RouteService` 负责重复进路、同站冲突以及进路锁闭状态恢复；
- `TemporarySpeedService` 负责活动限速范围重叠检测；
- 独立的操作规则函数负责方向允许的站别/接发类型，以及列车接发方式与活动进路的匹配；
- `MainWindow` 只收集界面输入、调用规则、展示统一弹窗并刷新控件状态；
- 按钮禁用是第一层防误操作，事件处理函数再次校验是第二层保护。

不把业务规则只写在按钮点击事件中，也不让绘图层承担状态判断。

## 4. 通信与操作门禁

### 4.1 通信状态

新增明确的“已连接站集合”。只有 A、B 两站均收到网络线程的 `connected` 事件时，才认定站间通信完成。仅有一端启动、服务器正在等待连接或单个线程处于运行状态，都不算通信完成。

### 4.2 初始状态

程序刚打开时：

- A站“启动通信”：可用；
- B站“启动通信”：可用；
- 两个“断开连接”：不可用；
- 区间改方、进路、临时限速、列车、仿真控制区域中的按钮：全部不可用。

第一站启动后，该站启动按钮禁用、断开按钮可用，另一站启动按钮继续可用。两站实际连接后解锁操作区，再按具体业务状态决定各按钮是否可用。

### 4.3 断线处理

任一端断开或发生网络断连时：

1. 自动暂停仿真计时器；
2. 清空本轮通信角色和已连接站集合；
3. 禁用全部业务操作；
4. 保留列车、进路和临时限速数据，避免断线造成业务状态丢失；
5. 两站恢复为可重新“启动通信”的状态。

所有业务入口在执行前再次校验完整通信状态。若通过代码或快捷路径绕过按钮禁用，仍弹出“站间通信未建立”错误。

## 5. 进路规则

### 5.1 方向允许表

| 当前方向 | 允许建立 |
|---|---|
| A站 → B站 | A站正线/侧线发车；B站正线/侧线接车 |
| B站 → A站 | B站正线/侧线发车；A站正线/侧线接车 |

不在允许表中的进路直接拒绝，不写入 `RouteService`。

### 5.2 重复与冲突

- 若相同车站、相同进路类型已经存在，提示“该进路已建立，请勿重复操作”；
- 若同站已有其他活动进路，提示现有进路名称和请求进路名称；
- 对向发车进路冲突沿用服务层校验，但错误信息包含两端站别和现有进路；
- 已锁闭进路不可人工取消，提示绑定列车编号。

## 6. 临时限速规则

设置新限速前，将起止区段换算为 38 区段顺序中的闭区间。只要与任一活动限速区间有交集，就拒绝设置，不再采用重叠取低。

错误信息必须包含：

- 拟设置范围和速度；
- 冲突限速编号；
- 冲突限速范围和速度；
- 处理建议：先取消冲突限速，或改用不重叠区段。

首尾相邻但没有共同区段的两个范围不算冲突。

## 7. 列车与开始仿真校验

“添加待发列车”只保存当时选择的发车方式和接车方式，不要求用户必须先建立进路。点击“开始仿真”时，对等待队列中的每一辆列车按其保存值进行校验。

### 7.1 站别映射

| 当前方向 | 发车站 | 到达站 |
|---|---|---|
| A站 → B站 | A站 | B站 |
| B站 → A站 | B站 | A站 |

### 7.2 匹配规则

- 正线发车必须匹配发车站 `1G` 发车进路；
- 侧线发车必须匹配发车站 `3G` 发车进路；
- 正线接车必须匹配到达站 `1G` 接车进路；
- 侧线接车必须匹配到达站 `3G` 接车进路。

任一待发列车不匹配时，仿真保持停止，不修改列车、进路或计时状态。弹窗显示列车编号、当前方向、选择的发车/接车方式、已建立进路和需要建立的正确进路。

等待队列为空时点击开始仿真，提示“当前没有待发列车，请先添加待发列车”。

## 8. 仿真与按钮状态机

所有状态集中由一个刷新函数计算，任何通信、列车、进路、限速或计时状态变化后调用。

| 控件 | 可用条件 |
|---|---|
| 启动通信 | 对应站未启动，且系统不在断线收尾 |
| 断开连接 | 对应站已启动 |
| 业务操作区 | A/B 两站均实际连接 |
| 开始仿真 | 通信完成且仿真未运行 |
| 暂停 | 通信完成且仿真正在运行 |
| 复位 | 通信完成且仿真正在运行 |
| 一键清车 | 通信完成且等待队列非空 |
| 取消选中限速 | 通信完成且存在有效限速并选中一项 |
| 取消选中进路 | 通信完成且选中未锁闭进路 |

暂停后“暂停”和“复位”立即禁用，“开始仿真”重新可用。待发列车发出、清除或复位后立即重新计算“一键清车”状态。

## 9. 复位语义

复位操作：

- 暂停引擎并把仿真时间归零；
- 清除全部待发、运行和停车列车；
- 释放列车造成的轨道占用；
- 保留全部已建立进路；
- 将所有 `LOCKED` 进路恢复为 `ESTABLISHED`，清空绑定列车编号；
- 保留活动临时限速；
- 重新计算信号、站内/区间编码和界面状态。

“一键清车”仍只清除列车，不承担复位时间和删除进路的职责，也不删除临时限速。

## 10. 错误弹窗格式

所有操作错误使用统一的警告弹窗，正文按三段组织：

```text
操作失败：<一句话结论>

当前状态：<方向、通信、现有进路或限速>
处理建议：<用户下一步应做什么>
```

弹窗标题使用具体业务名称，例如“进路建立失败”“临时限速设置失败”“仿真启动失败”，不直接向用户显示 Python 异常、内部枚举或堆栈信息。

## 11. 字体与下拉菜单样式

- 删除进路和临时限速区域单独设置的 `10px/11px` 字体；
- 继承应用公共字体，使其与区间改方、列车状态和通信面板一致；
- 保留紧凑布局，但通过尺寸策略和可读最小宽度避免文字裁切；
- 为 `QComboBox QAbstractItemView` 明确设置普通文字、背景、选中文字和选中背景；
- 选中项使用深色文字和浅蓝背景，禁用项使用灰色文字，避免 macOS 原生菜单出现白底白字。

## 12. 测试与验收

采用测试先行，至少覆盖：

1. 初始只有两站启动通信按钮可用；
2. 单站启动不解锁操作，两站 `connected` 后解锁，断线后重新锁定并暂停；
3. 两个方向各自只允许正确的发车站和接车站进路；
4. 重复进路、同站冲突和锁闭取消显示明确错误；
5. 重叠限速被拒绝，既有数据不变；相邻范围允许；
6. 开始仿真时正/侧线发车与接车进路均匹配才能启动；
7. 空等待队列不能启动；
8. 复位保留进路并解除锁闭，清除列车和占用；
9. 暂停、复位、清车、取消限速按钮随状态变化；
10. 下拉菜单样式包含可读的选中文字和选中背景；
11. 进路与限速字体继承公共字号；
12. 1440×900 和 1180×760 截图无裁切、遮挡或下拉菜单不可读问题。
